The lab

Which defence stops which attack.

The same attacks and the same honest payments, scored against five designs, from an agent that pays whatever it's told, through each rail's own controls, up to Warden with Claude reading the evidence. Every scenario runs on a fresh Warden with simulated rails. Nothing here is hand-scored.

What we do not claim

  • The attackers are ours. Forty attacks were written by Claude playing the attacker and six by hand. An independent red team would find others.
  • Rails are sandbox and testnet. Airwallex sandbox money, Alta testnet USDZ, a Visa test card behind Airi. The Visa credential was presented to a stand-in merchant checkout.
  • B1 is modelled, not run. "Rail controls only" applies each rail's documented controls (card merchant categories and limit, Airi passkey, Alta mandate payees and cap), set to the agent's own mandate. The four locks were also tested live with Warden switched off.
  • A fooled agent is assumed. Every attack request is sent exactly as the attacker wanted. Real agents often refuse; we don't count on it.
  • No formal proof, no independent review. The rules are checked after every action in simulation, not proved.
  • Recovery is not yet proven. The live dispute is still SUBMITTED, so "recovered" stays $0 until Airwallex reports it won.

Reproduce it

python -m warden.lab --offline        # B0 to B3, no keys needed
python -m warden.lab                  # adds B4 (Claude reads the evidence)
python -m warden.simulate             # 100,000 random actions, rules checked after each
python -m warden.simulate --sabotage  # mandate check switched off: the rules must catch it
python -m warden.receipts verify docs/live-runs/2026-11-13/receipts.jsonl docs/live-runs/2026-11-13/receipt-public-key.pem
